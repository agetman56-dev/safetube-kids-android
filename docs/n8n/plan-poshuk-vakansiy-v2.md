# План: воркфлоу пошуку роботи v2 (Київ, пріоритет мілтек)

Статус: чернетка до реалізації. Старий воркфлоу `6hpoabNO1K0CKosg`
(«Пошук вакансій мілтек — Київ») будується заново; старий не видаляти одразу —
відправити в архів і потримати тиждень.

## Що змінюємо принципово

| Старе | Нове |
|---|---|
| мілтек = жорсткий фільтр (AND) | мілтек = +25 до скору, ранжування |
| профіль вручну вписаний у промпт | резюме читається з Drive щоразу |
| AI лише для вакансій без зарплати | AI для всіх вакансій |
| дедуп у `$getWorkflowStaticData` | Data Table зі статусами |
| «позначив надісланими» до показу | статус `sent` тільки після успішної відправки |
| збір і оцінка в одному воркфлоу | два воркфлоу: збір / оцінка+дайджест |
| помилка джерела = тиша | health-таблиця + алерт «джерело дало 0» |
| ключ Jooble у URL вузла | credential / env |

## Архітектура: два воркфлоу

**WF-A «Збір вакансій» — кожні 6 год.**
Джерела → нормалізація → дедуп за хешем → запис у Data Table `vacancies`
зі статусом `new`. Без AI, без Telegram.

**WF-B «Оцінка і дайджест» — 09:00 і 18:00 (Europe/Kyiv).**
Читає `status = new` → резюме з Drive → AI-оцінка → скоринг → топ-10 у Telegram →
статус `sent`. Решта лишається в таблиці зі скором.

Навіщо ділити: збір ламається часто (верстка, 403), оцінка коштує грошей.
Розділення дає ретрай збору без повторної оплати AI, видимість по кожному
джерелу окремо, і головне — вакансія не зникає, якщо відправка впала.

## Джерела

1. **Jooble API** — стабільне, ключ у credential, пагінація (`page` 1..3).
2. **Telegram-канали** через `t.me/s/<channel>` — `miltech_jobs_ua`, `lobbyx`,
   +1-2 складські. Парсити пост цілком одним проходом (не склеювати масиви
   `ids` і `texts` за індексом — саме тут старий воркфлоу підставляв чужі лінки).
3. **work.ua** — 5-6 запитів × 2-3 сторінки. Перевіряти HTTP-статус, а не ковтати
   сторінку блокування. Опис вакансії тягнути другим запитом (у старому `body`
   був порожній, і AI судив по самій назві).
4. **robota.ua** — імовірно є публічний JSON-ендпоінт пошуку; потребує перевірки.
5. **Lobby X (тільки цивільні)** — `www.thelobbyx.com`.
   `lobbyx.army` НЕ підключаємо взагалі. Спосіб доступу з'ясувати на кроці 0.

## Фільтр «цивільні вакансії»

Дві незалежні перевірки, бо ціна помилки — сміття в дайджесті:
- **код**, стоп-слова: `військовослужбовц`, `контракт зі зсу`, `мобіліз`,
  `бойов* посад*`, `в/ч`, `вос `, `стройов`, `тцк`, `нгу`, `дшв`, `сзч`,
  `рекрутинг до`, `служба за контрактом`;
- **AI**, поле `is_military_service: bool` у структурованій відповіді.

Спрацювання будь-якої з двох → `status = skipped` з причиною (не викидати мовчки,
щоб можна було перевірити хибні спрацювання).

## Data Tables

**`vacancies`** — `hash` (ключ), `link`, `source`, `title`, `company`, `city`,
`salary_raw`, `salary_uah_min`, `body`, `found_at`, `status`
(`new|scored|sent|applied|rejected|skipped`), `skip_reason`, `fit_score`,
`total_score`, `is_miltech`, `is_military_service`, `one_line`, `sent_at`.

**`miltech_companies`** — `name`, `aliases`, `note`. Список зі ~120 назв переїжджає
з коду в дані; звірка за підрядком і нормалізацією (в старому був `indexOf` на
точну рівність — практично ніколи не спрацьовував).

**`sources_health`** — `source`, `run_at`, `items_found`. Алерт, якщо джерело дало
0 три запуски поспіль.

Дедуп-ключ: `sha1(нормалізований link без utm)`; для Telegram-постів без стабільного
лінка — `sha1(title|company|city)`. Пам'ять 60 днів.

## Оцінка і скоринг

AI (gpt-5-mini) отримує текст резюме `Гетьман_Олександр_Резюме_комірник.docx`
(Drive ID `1yAjdNrufHwWPkm74FS38-IFreQZgo5aW`, читається щоразу — оновив файл,
змінилась логіка добору) + дані вакансії. Structured output:

```json
{"fit_score": 0-100, "is_miltech": false, "is_military_service": false,
 "matched": ["..."], "gaps": ["..."], "one_line": "чому підходить"}
```

Скор рахується кодом, не моделлю:

```
total = fit_score
      + 25  якщо is_miltech
      + 10  якщо salary_uah_min >= 40000
      -100  якщо is_military_service
```

Поріг показу `total >= 50`. Дайджест — топ-10 з рядком «чому підходить», під ним
«ще N вакансій зі скором 50+ у таблиці».

Зарплата: брати ВЕРХНЮ межу діапазону, не нижню (старий парсер брав мінімум і
відсікав «25 000 – 45 000»). Поріг 40k — бонус, а не відсів: частина мілтек-компаній
зарплату не публікує.

## Порядок робіт (вечір)

0. **Розвідка Lobby X** (~15 хв) — пробним HTTP-вузлом у n8n: чи є JSON/RSS,
   як виглядають URL фільтрів по місту й категорії, чи є там складські вакансії
   в Києві взагалі. Від результату залежить, чи Lobby X — HTTP-джерело, чи
   запасний варіант через канал `@lobbyx`.
1. **Data Tables** (~30 хв) — три таблиці, залити список мілтек-компаній.
2. **WF-A, база** (~1 год) — Jooble + Telegram (найстабільніші), прогін end-to-end,
   перевірка записів у таблиці.
3. **WF-A, решта джерел** (~45 хв) — work.ua, robota.ua, Lobby X, health-алерти.
4. **WF-B** (~1 год) — резюме, AI, скоринг, дайджест, статуси.
5. **Тестовий прогін** — дивитись передусім на `skipped` і причини, а не на показане.
6. **Активація** — розклад у Europe/Kyiv, error workflow `86CjX2IyE0JWOQm6`,
   старий воркфлоу в архів.

Етап 4 (окремо, за бажанням): кнопки «👍 подався / 👎 не цікаво» під вакансіями →
callback → статус у таблиці → відхилені компанії знижують скор наступних.
